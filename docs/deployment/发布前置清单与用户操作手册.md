# 发布前置清单与用户操作手册（energytools v0.1.0）

> **本文档定位**：面向**发布操作人**（仓库所有者）的逐条操作手册。把「从零开始把本项目发布到 GitHub + Read the Docs」拆成 6 个事项，每个事项逐条列出**用户操作 / 自动操作**、给出**决策表**与**验收标准**，并附**仓库描述**与**发布文案草稿**。
>
> **范围声明**：本文档只描述账号注册、平台绑定、仓库创建、项目导入、webhook、域名等**平台级操作**。`pyproject.toml`、`.readthedocs.yaml`、Sphinx `conf.py`、CI 等**代码/配置文件一律不在此分支实施**（分别由「多安装方式打包脚手架」「文档构建与 readthedocs 发布管线」「rtd 构建管线补全与本地验证」等分支负责）。本文档涉及的仓库/平台事实以项目现状为准（见 [项目现状](#0-项目现状与术语)）。

### 0.2 术语表

| 术语 | 含义 |
|---|---|
| GitHub 仓库（repo） | 代码托管仓库，文档的**唯一源**（Single Source of Truth） |
| Read the Docs（RTD） | 文档托管平台；社区版 readthedocs.org 免费，要求仓库**公开** |
| RTD 项目（project） | RTD 上一个文档项目，与一个 Git 仓库一一对应 |
| slug | RTD 项目的 URL 标识；本项目目标 slug = `energytools-refactored`，默认域名 `https://energytools-refactored.readthedocs.io/` |
| webhook | GitHub 事件 → RTD 构建的自动触发通道；RTD 导入项目时**自动安装** |
| 版本（version） | RTD 的 `latest`（默认分支）、`stable`（最新 tag）、以及按分支/tag 生成的版本 |
| PR 构建（pull request builds） | 对 GitHub PR 预构建文档（可选，需在 RTD 高级设置开启） |
| CNAME | DNS 记录类型；自定义域名接入 RTD 的方式 |
| OAuth | RTD「用 GitHub 登录 / 连接 GitHub 账户」的授权机制 |
| 徽章（badge） | README 中显示的「docs 构建状态」图片链接 |

## 1. 总体流程

```
阶段 A          阶段 B           阶段 C            阶段 D          阶段 E          阶段 F
GitHub 仓库 ──► RTD 注册绑定 ──► 项目导入 ──► webhook 确认 ──► 域名配置 ──► 验收与发布
（创建）        （账号/OAuth）    （首次构建）      （自动/兜底）    （子域名/自定义）  （描述+文案）
```

- 阶段 A–B 是**纯用户操作**（无自动环节），C–E 是「用户操作 + 平台自动操作」混合，F 是**内容产出**（本文第 8 节已给草稿）。
- 每个阶段的「操作方」用两种标记：**👤 用户操作**（必须人工完成，通常不可自动化或自动化风险高）／**🤖 自动操作**（平台自动完成，用户只需验收）。
- 所有阶段的**通过标准**汇总见 [第 9 节验收总清单](#9-验收总清单)。

## 2. 事项一：GitHub 仓库创建

### 2.1 决策表

| 决策ID | 决策点 | 选项 | 推荐 | 后果 / 影响 |
|---|---|---|---|---|
| D1 | 仓库所有者 | A. 个人账号<br>B. 组织（Organization） | **B（如有组织）**，否则 A | 组织便于多人协作与所有权归属；个人账号后续迁移到组织需改 remote 与 RTD 关联 |

| D2a | 默认分支名 | A. `main`<br>B. 其他 | **A. `main`** | RTD 默认构建 `main`；`latest` 版本自动跟随默认分支 |
| D2b | 初始化内容 | A. 空仓库，本地推送<br>B. 带 README/license/.gitignore 初始化 | **B 但以本地已有文件为准** | 本地已有 README、docs 等，**不要**勾选 GitHub 自动生成的 README/license（避免冲突）；.gitignore 本地已有 |

### 2.2 操作清单（用户操作 / 自动操作）

| # | 操作方 | 操作 | 期望结果 | 验收方式 |
|---|---|---|---|---|
| 1 | 👤 用户 | 登录 GitHub → New repository：Owner（按 D1）、Repository name = `energytools`、**Public**（按 D2）、默认分支 `main`（按 D2a）；**不勾选**自动生成 README/.gitignore/license（按 D2b） | 仓库 `https://github.com/<owner>/energytools` 创建成功 | 浏览器打开仓库 URL 可见空仓库页 |
| 2 | 🤖 自动 | GitHub 初始化仓库（空仓库、默认分支 `main`） | 仓库页出现「…or push an existing repository」指引 | 仓库页可见 push 指引 |
| 3 | 👤 用户 | 本地推送既有内容：`git remote add origin git@github.com:<owner>/energytools.git`；`git push -u origin main`（把本地 `main` 内容推送；中文任务分支按团队流程合并后再推） | 本地文件（pyproject.toml、README.md、docs/、src/、pixi.toml 等）出现在 GitHub | GitHub 仓库文件列表与本地一致 |
| 4 | 👤 用户 | 填写仓库描述（草稿见 [8.1](#81-github-仓库描述草稿)）、Topics（见 [8.1](#81-github-仓库描述草稿)） | 仓库页展示描述与话题标签 | 仓库页可见描述与 topics |
| 5 | 👤 用户 | （可选）Settings → 设置默认分支为 `main`、启用分支保护（要求 PR 审查） | main 受保护 | Settings → Branches 显示保护规则 |

### 2.3 注意

- **仓库名 = slug 的前置条件**：RTD slug 默认取仓库名。若 `energytools` 被占用，RTD 会提示 slug 冲突（见 [4.3](#43-注意)）。
- GitHub 描述上限 **350 字符**；Topics 上限 **20 个**。
- 本阶段结束标志：`https://github.com/<owner>/energytools` 可访问、内容与本地一致、描述与 topics 已填。

## 5. 事项四：webhook 配置

### 5.1 决策表

| 决策ID | 决策点 | 选项 | 推荐 | 后果 / 影响 |
|---|---|---|---|---|
| D5 | webhook 来源 | A. RTD 导入时自动安装（默认）<br>B. 手动在 GitHub 创建<br>C. 不配置（仅手动「Build latest」） | **A，B 作为兜底** | A/B：push 到 `main` 自动触发文档构建；C：每次发布需人工点构建，易漏，不推荐 |
| D6 | PR 构建（pull request builds） | A. 开启<br>B. 关闭 | **A（团队协作期）** | 开启后每个 PR 生成预览文档，便于文档审查；代价是多一次构建 |
| D6a | 构建触发事件 | push（默认）｜ 也可加 tag（打 tag 自动构建版本） | push + tag | tag 构建是 `stable` 版本正确指向发布版本的保障（配合 [8.3](#83-github-release-文案草稿) 的 tag 操作） |

### 5.2 操作清单

| # | 操作方 | 操作 | 期望结果 | 验收方式 |
|---|---|---|---|---|
| 1 | 🤖 自动 | 项目导入时 RTD 在 GitHub 仓库自动安装 webhook（push 事件） | GitHub 仓库 Settings → Webhooks 出现 readthedocs 条目 | Settings → Webhooks 可见条目 |
| 2 | 👤 用户 | **验证**：本地 `git push` 到 `main` → RTD Builds 自动出现新构建 | push 后 ~1 分钟内 Builds 页出现 build #N | 观察 Builds 页自动刷新 |
| 3 | 👤 用户 | （仅当自动 webhook 缺失时的兜底）GitHub Settings → Webhooks → **Add webhook**：Payload URL = `https://readthedocs.org/api/v2/webhook/<slug>/<token>/`（slug 与 token 见 RTD Admin → Integrations 中 GitHub incoming webhook 条目）；Content type = `application/json`；事件选 **Just the push event**；Active 勾选 | GitHub 显示 webhook 已创建（Recent Deliveries 可测试） | 发一次测试推送 → RTD 触发构建 |
| 4 | 👤 用户 | （按 D6）RTD Admin → Advanced Settings → 勾选 **Build pull requests for this project** → Save | 开启 PR 构建 | 新建一个 PR → RTD 出现该 PR 的构建 |
| 5 | 👤 用户 | （按 D6a）确认 tag 推送会触发构建：`git tag v0.1.0 && git push origin v0.1.0`（正式发布时执行） | RTD 构建版本 `v0.1.0`，`stable` 自动指向它 | Versions 页出现 `v0.1.0`，`stable` 标记更新 |

### 5.3 注意

- 若自动 webhook 未出现，最常见原因是 OAuth 授权时未授予仓库 webhook 管理权限——重新在 RTD Settings → Connected Accounts 中刷新授权，或直接走步骤 3 的手动兜底（手动兜底**必须**，否则 push 不触发构建）。
- webhook 测试（Recent Deliveries → Redeliver）是快速排障手段；失败响应体含原因。
- 本阶段结束标志：push / tag / PR 三种事件（按决策启用）都能自动触发构建。

## 6. 事项五：域名

### 6.1 决策表

| 决策ID | 决策点 | 选项 | 推荐 | 后果 / 影响 |
|---|---|---|---|---|
| D7 | 域名策略 | A. 使用 RTD 默认子域名 `https://energytools-refactored.readthedocs.io/`（免费、零操作）<br>B. 自定义域名（如 `docs.energytools.dev`，需自有域名 + DNS 操作） | **发布初期选 A**；有自有域名且希望品牌统一时选 B（可后续再启用） | A：无需任何 DNS 操作，TLS 由 RTD 自动管理；B：需要域名所有权、CNAME 记录、等待证书签发（分钟级~数小时），与 A 可并存（两者同时有效） |
| D7a | （若选 B）自定义域名形式 | A. 子域名 `docs.energytools.dev`<br>B. 根域（apex）`energytools.dev` | **A. 子域名** | 子域名只需一条 CNAME；根域要求 DNS 服务商支持 CNAME 扁平化/ALIAS（部分服务商不支持，且与 MX 等记录易冲突） |
| D7b | （若选 B）TLS 证书 | RTD 自动签发（Let's Encrypt） | 自动 | 无需用户操作；签发期间域名短暂不可用属正常 |

### 6.2 操作清单（默认子域名，选项 A）

| # | 操作方 | 操作 | 期望结果 | 验收方式 |
|---|---|---|---|---|
| 1 | 🤖 自动 | RTD 为项目提供 `https://energytools-refactored.readthedocs.io/`（含自动 TLS） | 域名可访问 | 浏览器访问通过，地址栏显示安全锁 |
| 2 | 👤 用户 | 将默认域名写入仓库描述与 README 徽章（草稿见 [8.1](#81-github-仓库描述草稿) / [8.2](#82-readme-徽章草稿)） | 对外文案统一指向文档地址 | 仓库页描述含文档链接且可点 |

### 6.3 操作清单（自定义域名，选项 B）

| # | 操作方 | 操作 | 期望结果 | 验收方式 |
|---|---|---|---|---|
| 1 | 👤 用户 | RTD Admin → **Domains** → Add Domain → 输入 `docs.energytools.dev`（按 D7a）→ 记下弹窗给出的 CNAME 目标值 | RTD 显示待验证域名 | Admin → Domains 出现该域名，状态 pending |
| 2 | 👤 用户 | 在域名 DNS 服务商处添加 **CNAME**：`docs` → RTD 弹窗给出的目标（通常为 `readthedocs.io` 或项目子域名，**以弹窗为准**）；TTL 取默认 | DNS 生效（可先 `nslookup docs.energytools.dev` 自测） | 本机/公共 DNS 解析结果包含 CNAME 目标 |
| 3 | 🤖 自动 | RTD 检测到 CNAME → 校验域名所有权 → 通过 Let's Encrypt 签发证书并配置 https | 域名状态变为有效，https 可用 | Admin → Domains 状态为 valid；浏览器 https 访问通过、证书链完整 |
| 4 | 👤 用户 | 验收：`https://docs.energytools.dev/en/latest/` 与 `https://energytools-refactored.readthedocs.io/en/latest/` **同时可访问** | 双域名均正常（自定义域名启用后默认子域名仍保留） | 两个 URL 分别打开 |

### 6.4 注意

- **CNAME 目标值以 RTD 添加域名弹窗显示为准**，不同时期/地区展示可能不同；本文不写死。
- 证书签发一般分钟级完成；若超过数小时仍 pending，检查 CNAME 是否被 CDN/代理服务干扰（如有 CDN 需求，按 RTD 文档配置）。
- 自定义域名启用后，**默认子域名依然有效**，可随时在 Domains 中删除自定义域名回退。
- 本阶段结束标志：默认子域名（必选）或自定义域名（可选）https 可访问。

## 7. 决策表汇总

| 决策ID | 决策点 | 推荐值 | 后果（若不推荐） |
|---|---|---|---|
| D1 | 仓库所有者 | 组织（或个人） | 迁移所有权需改 remote 与 RTD 关联 |
| D2 | 仓库可见性 | **Public** | 私有 → RTD 社区版不可用，需 for Business（付费） |
| D2a | 默认分支 | `main` | RTD `latest` 跟随其他分支，需额外配置 |
| D2b | 初始化内容 | 不用 GitHub 自动生成 README/license | 与本地文件冲突、覆盖本地内容 |
| D2c | 仓库名 | `energytools` | slug/URL 不一致，改名成本高 |
| D3 | RTD 登录 | GitHub OAuth | 邮箱注册需二次绑定 GitHub |
| D3b | RTD 版本 | 社区版（免费） | 商业版付费；私有仓库才需要 |
| D4 | 导入方式 | 连接账户自动导入 | 手动导入需补 webhook |
| D4a | slug | `energytools` | 被占用则改名，域名随之改变 |
| D4b | 首次构建配置 | 依赖文档分支交付 `.readthedocs.yaml` / `conf.py` | 配置未就绪时首次构建失败（预期内） |
| D5 | webhook | 自动安装（手动兜底） | 无 webhook → push 不自动构建 |
| D6 | PR 构建 | 开启 | 关闭则 PR 无文档预览 |
| D6a | 触发事件 | push + tag | 不打 tag 则 `stable` 不更新 |
| D7 | 域名策略 | 默认子域名（自定义可后补） | 自定义域名需 DNS 操作与证书等待 |
| D7a | 自定义域名形式 | 子域名 `docs.…` | 根域需 CNAME 扁平化支持 |
| D7b | TLS | RTD 自动（Let's Encrypt） | 无 |

## 11. 故障排查速查表

| 症状 | 可能原因 | 排查 / 处置 |
|---|---|---|
| push 后 RTD 不自动构建 | webhook 缺失或失效 | GitHub Settings → Webhooks 检查条目；缺失则按 [5.2 步骤 3](#52-操作清单) 手动创建；Recent Deliveries 重发测试 |
| 首次构建失败 | `.readthedocs.yaml` / `conf.py` 未就绪 | 属「文档构建」分支交付前提，非本分支缺陷；确认依赖安装与构建日志 |
| slug 被占用 | `energytools-refactored.readthedocs.io` 已被他人使用 | 导入时改名（如 `energytools-sia2024`），同步更新本文 8.1/8.2 的 URL |
| 自定义域名一直 pending | CNAME 未生效 / 被 CDN 干扰 | `nslookup docs.energytools.dev` 核对记录；与 RTD 弹窗目标比对；等待后刷新 |

| `stable` 版本未更新 | 未打 tag 或 tag 构建失败 | `git tag v0.1.0 && git push origin v0.1.0`；检查 Versions 页 |
| 私有仓库导入失败 | 社区版不支持私有 | 改为公开，或评估 Read the Docs for Business |
